# Decisions

## 2026-11-08 Database: SQLite through SQLAlchemy

- **Decision:** SQLite, accessed through SQLAlchemy.
- **Why:** Zero cost, one file, no extra service for peer reviewers to run. Data volume is small (scenarios and
  audit entries). SQLAlchemy keeps a later move to Postgres cheap.
- **Alternatives:** Postgres in docker-compose (more setup, a second container); managed Postgres such as
  Cloud SQL or Supabase (cost and account setup).

## 2026-11-08 Auth: demo logins with signed JWT roles

- **Decision:** FastAPI issues a signed JWT for a demo Analyst or Reviewer login. The role is in the token and
  checked on each endpoint. Demo logins hold no real credentials.
- **Why:** Enough to show the approval workflow, no external service, works offline in docker-compose.
- **Alternatives:** Supabase Auth (outside the stack, needs an account); session cookies (more state to manage).

## 2026-11-08 Gate 3: pricing-service gaps filled by a change request

- **Decision:** Ask the pricing service for a metadata endpoint, histogram counts and projected A/E. The backend
  only translates. See `_docs/contract-check.md`.
- **Why:** Keeps monitoring and rating-adjacent logic out of this repo.
- **Alternatives:** Backend derives them (breaks the no-rating-logic rule); drop the UI fields (loses plan
  features).

## 2026-11-08 Hosting: always-free e2-micro VM with docker-compose (portable)

- **Decision:** One always-free GCP e2-micro VM in a free-tier US region (us-west1, us-central1 or us-east1),
  running docker-compose with three services: Caddy (static SPA build, reverse proxy of `/api`, automatic HTTPS
  on a free sslip.io hostname), the backend (SQLite on a mounted volume on the VM's persistent disk), and the
  published pricing-service image, reachable on the compose network only. A 1 GB swap file is added. Budget
  alert at £1.
- **Portability rules:** all config through environment variables; the frontend calls relative `/api` paths;
  schema changes only through Alembic migrations; everything VM-specific lives in `deploy/`.
- **Why:** Lowest cost, SQLite data persists across restarts, and the same compose file runs locally and for peer
  reviewers. Measured pricing service memory is about 70 MiB, so 1 GB plus swap should fit.
- **Costs (checked 8 Nov 2026):** VM and 30 GB standard disk are free. Not free: the external IPv4 address,
  about $0.005 per hour (about $3.65 a month, about $7.30 for two months); egress beyond 1 GB a month (small
  for a demo). Prices from secondary sources, to be confirmed on the billing page when the VM is created.
- **Alternatives:** Cloud Run with a sidecar and reseeded SQLite (cheaper in effort, data resets); Cloud Run with
  Cloud SQL (about £8-10 a month).
- **Also decided:** The frontend becomes a static SPA build, served by Caddy, as its own backlog task. Approved
  dependencies: SQLAlchemy, Alembic, Caddy (image).

## 2026-11-08 Scope change after reading the course rubric

- **Decision:** MCP server, agent pack and security scan move to Future to-do (not scored). Added observability,
  an alert on user impact and a stretch on-call agent. CI/CD targets 2 of 3 points. Tests cover unit, frontend
  and integration with one command. Each task records its self-check as an issue comment. Timeline starts 8 Nov.
- **Why:** The rubric (12 criteria, 24 points, 10 to pass) scores observability, alerting and the on-call agent
  and does not score MCP or security scanning.
- **Alternatives:** Keep the MCP server as an unscored demo feature; build a dev/prod split for 3 CI/CD points
  (needs a second VM, not free).

## 2026-11-08 Static SPA build through a separate Vite config

- **Decision:** `npm run build` uses `frontend/vite.spa.config.ts` (TanStack Start in SPA mode, no Nitro, output in
  `dist/client`). The Lovable config stays as `npm run build:lovable`.
- **Why:** The Lovable config always adds Nitro with a Cloudflare target and did not write an `index.html` in SPA
  mode. The plain config produces a prerendered shell that Caddy serves with an index.html fallback.
- **Alternatives:** Run the Nitro Node server as a third container (more memory on the 1 GB VM); patch the Lovable
  config (fragile, it is regenerated by Lovable).
